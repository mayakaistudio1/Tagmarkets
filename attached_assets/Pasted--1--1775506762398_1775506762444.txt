Задача 1. Мультиязычное событие для одного вебинара
Проблема

Сейчас в админке для события можно выбрать только один язык: либо RU, либо DE.
Но AMA с Niklas должна идти на двух языках, и событие должно корректно отображаться пользователям с разным выбранным языком интерфейса.

Что нужно сделать

Добавить возможность для отдельных событий задавать multi-language event вместо одного языка.

Логика

Для конкретного события админ должен иметь 3 варианта:

RU only
DE only
Multilanguage / RU + DE
Как должно работать на фронте

Если событие помечено как Multilanguage:

оно показывается и пользователям с RU-интерфейсом, и пользователям с DE-интерфейсом
текст интерфейса карточки события отображается на языке интерфейса пользователя
при этом само событие может иметь:
либо один общий title, если он нейтральный
либо отдельные title/subtitle для RU и DE
Желательно

Добавить в структуру события поля:

title_ru
title_de
description_ru
description_de
language_mode = ru | de | multi
Отображение

Если language_mode = multi:

в карточке можно показать пометку:
RU / DE
или иконку двух языков
дата, время, speaker, кнопки — как обычно
текст кнопок и интерфейсных подписей берутся из выбранного языка пользователя
Цель

Чтобы одно событие не приходилось дублировать дважды только из-за языков.

Задача 2. Предварительные вопросы для конкретного AMA-события
Что нужно сделать

Добавить для конкретного события возможность собирать предварительные вопросы от пользователей.

Важно

Это должно работать не для всех событий по умолчанию, а только если функция включена в админке для выбранного вебинара.

Что добавить в админке события

Чекбокс / переключатель:

Enable pre-submitted questions
при включении появляется дополнительная настройка:
question_label_ru
question_label_de
question_label_en если нужно
опционально: question_deadline
опционально: question_hint
Поведение в Partner App

Если у события включена функция вопросов:

на карточке этого события появляется дополнительная кнопка:
RU: Задать вопрос
DE: Frage stellen
EN: Submit question
Flow

После нажатия:

открыть форму или простой input flow
пользователь вводит вопрос
вопрос сохраняется с привязкой к:
event id
user id / telegram id
name
surname
selected language
timestamp
после отправки показать подтверждение:
RU: Ваш вопрос сохранён
DE: Deine Frage wurde gespeichert
EN: Your question has been saved
Что нужно в админке

Внутри админки события сделать отдельный блок:
Submitted Questions
где видно:

имя
фамилия
username / telegram id
язык
текст вопроса
дата/время
статус, если захотите:
new
selected
answered
Цель

Чтобы заранее собирать вопросы именно под AMA с Niklas, не создавая отдельного бота и не ломая текущую механику.

Вопрос разработчику

На главной странице / странице списка предстоящих вебинаров, прямо в карточке конкретного AMA-события, кроме кнопок:

Invite / Пригласить

добавить ещё одну кнопку:

Задать вопрос / Frage stellen

Если нельзя красиво вместить 3 кнопки, можно ли сделать:
вторую строку действий

Предпочтительный вариант

Лучше всего, если:

на странице расписания у конкретного AMA сразу есть кнопка “Задать вопрос”
но появляется она только для событий, где это включено в админке

Так пользователь видит действие сразу, без лишних переходов.

Как можно коротко поставить задачу разработчику

Нужно внести 3 доработки в Partner App:

1. Multilanguage event support
Сейчас событие можно пометить только одним языком. Нужно добавить режим multi, чтобы одно событие могло отображаться и RU-, и DE-пользователям, а интерфейс карточки подстраивался под выбранный язык пользователя.

2. Pre-submitted questions per event
Для отдельных событий в админке нужен флаг Enable pre-submitted questions. Если он активирован, у события появляется кнопка “Задать вопрос”, пользователь может отправить вопрос, а в админке эти вопросы сохраняются внутри конкретного события.

3. Question button in webinar schedule UI
Нужно проверить, можно ли прямо в карточке AMA-события на странице расписания добавить отдельную кнопку “Задать вопрос”, которая показывается только если для события включён сбор вопросов.
