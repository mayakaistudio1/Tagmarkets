# Partner Mini App – FIXES

## 1. Поведение персонального AI Invite

- Контекст: Партнёр отправляет персональный AI‑инвайт (через квалификацию, генерацию текста и отправку ссылки гостю).
- Проблема:
  - Факт перехода по ссылке и начала диалога с ассистентом не попадает в статистику, пока гость не заполнит форму регистрации (email, WhatsApp, Telegram и т.д.).
- Ожидаемое поведение:
  - Фиксировать отдельный статус для контакта:
    - `link_opened` – гость перешёл по ссылке и начал диалог, но ещё не заполнил форму.
    - `registered` – гость заполнил форму и подтвердил регистрацию на вебинар.
    - В дальнейшем возможен статус `attended` / `no_show`.
  - Эти статусы должны быть видны в хабе партнёра и в отчётах по мероприятиям.

## 2. UX в воронке приглашения

- Контекст: Гость открывает персональную ссылку, общается с ассистентом и видит информацию о вебинаре.
- Проблемы:
  - Нет понятного способа «вернуться назад» или выйти в более общий экран после диалога с ассистентом.
  - В тексте обещана кнопка «зарегистрироваться», но она не всегда видна или логически расположена.
- Ожидаемое поведение:
  - Добавить понятную навигацию (кнопка/ссылка «Назад» или «Выйти в главное меню»).
  - Обеспечить, чтобы кнопка регистрации всегда была:
    - визуально заметна;
    - логически привязана к CTA, который озвучен в тексте.

## 3. Экран после регистрации гостя

- Контекст: Гость заполнил форму регистрации и подтвердил участие в вебинаре.
- Проблема:
  - Сразу показывается кнопка «Join / Присоединиться на Zoom», даже если вебинар через несколько дней.
- Ожидаемое поведение:
  - Разделить «экран после регистрации» и «экран / состояние в момент начала вебинара»:
    - После регистрации:
      - Показать подтверждение регистрации (дата, время, формат, что будет на вебинаре).
      - Показать информацию, как гость получит ссылку на Zoom (например, за 15 минут до старта по email/Telegram).
    - В момент начала вебинара:
      - Показывать кнопку «Join / Присоединиться в Zoom», если до события меньше N минут.

## 4. Статистика по предстоящим мероприятиям

- Контекст: Хаб партнёра → Предстоящие мероприятия.
- Проблема:
  - Нет статистики:
    - кому отправлены AI‑инвайты;
    - кому отправлены обычные social‑инвайты;
    - сколько ссылок отправлено;
    - сколько переходов по ссылке (клики);
    - кто перешёл, но не зарегистрировался.
- Ожидаемое поведение:
  - Для каждого предстоящего мероприятия показывать, как минимум:
    - Кол-во AI‑инвайтов (отправлено / перешли / зарегистрировались).
    - Кол-во social‑инвайтов (отправлено / перешли / зарегистрировались).
  - По возможности – дать партнёру доступ к списку контактов с их статусами.

## 5. Статистика по прошедшим мероприятиям

- Контекст: Хаб партнёра → Прошедшие мероприятия.
- Проблемы:
  - В отчёте может быть метрика «3 посетили», но в списке контактов этих трёх людей не видно.
  - Нельзя увидеть по каждому контакту, был он или нет, и сразу запустить AI follow‑up.
- Ожидаемое поведение:
  - Для каждого прошедшего мероприятия:
    - Показывать список контактов:
      - `registered` + `attended` (пришёл).
      - `registered` + `no_show` (не пришёл).
    - Давать возможность запустить AI follow‑up по каждому контакту прямо из отчёта.
  - Числовые метрики «пригласил / зарегистрировались / посетили» должны совпадать со списками и статусами контактов (без «фантомных» посетителей).

## 6. Страница мероприятия по общей ссылке

- Контекст: Партнёр делится просто страницей мероприятия (без персонального AI‑инвайта), через кнопку «поделиться мероприятием».
- Проблема:
  - Страница мероприятия, открытая по такой общей ссылке, недоступна (возникает ошибка / пустой экран).
- Ожидаемое поведение:
  - По общей ссылке мероприятие должно:
    - Открываться корректно (детали события, дата/время, описание).
    - Давать возможность зарегистрироваться.
  - Источник регистрации по этой ссылке должен всё равно корректно попадать в статистику мероприятия (как общий social‑инвайт / прямой линк).
